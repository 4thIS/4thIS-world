이 PR 고유 제약 (스펙 §13 + 팀 공통 결정):

- 컨테이너 1개, 프로세스 1개(`node`가 PID 1, wj#1의 SIGTERM 처리로 정상 종료). 볼륨 `world-data:/data`에 `world.db` 하나.

- 비루트 사용자(`node`, uid 1000). 헬스체크는 `/api/health` (이미지에 curl이 없어서 `node -e fetch(...)`).

- SPA fallback 제외: `/api`, `/socket.io`, 확장자가 있는 경로(없는 파일은 JSON 404), GET·HEAD 외 메서드.
- 리버스 프록시는 WebSocket 업그레이드 헤더를 넘겨야 한다(문서에 nginx 예시).
- cw#4의 E2E는 컨테이너 없이 `npm run start -w @4this/server`로 서버를 띄우고 `WEB_DIST`·`DB_PATH`·`ADMIN_PASSWORD`·`SESSION_SECRET`·`PORT`를 넘긴다. 이 명령의 작업 폴더는 `apps/server`라서 **상대 경로는 `apps/server` 기준**이다(예: `WEB_DIST=../web/dist`, `DB_PATH=./data/e2e.db`). 절대 경로를 쓰면 헷갈리지 않는다.

- [ ] **Step 5: 404 처리 분리**

`setNotFoundHandler`는 한 번만 등록할 수 있어서 `registerErrorHandlers`에서 빼고 함수로 내보낸다. 바뀐 부분: import에 `FastifyReply`, `FastifyRequest` 추가, 주석 "모든 오류를…", 맨 아래 `sendNotFound`. 고친 뒤 파일 전체:

`apps/server/src/errors.ts`:

```ts
import type { FastifyError, FastifyInstance, FastifyReply, FastifyRequest } from 'fastify';
import type { z } from 'zod';
import type { ApiErrorBody, ApiErrorCode } from '@4this/shared';

/** 라우트에서 throw하면 ApiErrorSchema 모양으로 응답한다 */
export class HttpError extends Error {
  constructor(
    readonly statusCode: number,
    readonly code: ApiErrorCode,
    message: string,
    readonly detail?: unknown,
  ) {
    super(message);
    this.name = 'HttpError';
  }
}

export const unauthorized = (message = '로그인이 필요합니다') =>
  new HttpError(401, 'unauthorized', message);
export const forbidden = (message = '권한이 없습니다') => new HttpError(403, 'forbidden', message);
export const notFound = (message = '찾을 수 없습니다') => new HttpError(404, 'not_found', message);

/** shared zod 스키마로 검사한다. 실패하면 400 invalid, detail에 zod 이슈 목록 */
export function parse<S extends z.ZodType>(schema: S, value: unknown): z.infer<S> {
  const result = schema.safeParse(value);
  if (!result.success) {
    throw new HttpError(400, 'invalid', '입력값이 올바르지 않습니다', result.error.issues);
  }
  return result.data;
}

function body(code: ApiErrorCode, message: string, detail?: unknown): ApiErrorBody {
  return detail === undefined ? { error: code, message } : { error: code, message, detail };
}

/** 모든 오류를 ApiErrorSchema 모양으로 바꾼다 */
export function registerErrorHandlers(app: FastifyInstance): void {
  app.setErrorHandler((error: FastifyError | HttpError, request, reply) => {
    if (error instanceof HttpError) {
      return reply.status(error.statusCode).send(body(error.code, error.message, error.detail));
    }
    const status = error.statusCode ?? 500;
    if (status === 429) {
      return reply.status(429).send(body('rate_limited', '잠시 후 다시 시도하세요'));
    }
    if (status >= 400 && status < 500) {
      return reply.status(status).send(body('invalid', error.message));
    }
    request.log.error(error);
    return reply.status(500).send(body('internal', '서버 오류가 발생했습니다'));
  });
}

/** 없는 경로: 404 not_found. WEB_DIST가 있으면 static.ts의 SPA 처리가 먼저 본다 */
export function sendNotFound(request: FastifyRequest, reply: FastifyReply) {
  return reply
    .status(404)
    .send(body('not_found', `${request.method} ${request.url} 경로가 없습니다`));
}
```

- [ ] **Step 6: 정적 서빙 구현**

`cacheControl: false`로 `@fastify/static`의 기본 캐시 헤더를 끄고 `setHeaders`에서 파일 경로별로 정한다. SPA fallback은 `reply.sendFile('index.html')`(플러그인이 붙이는 데코레이터)로 보낸다. Socket.IO(wj#3)는 http 서버의 요청을 `/socket.io/`에서 먼저 가로채므로 Fastify의 404 처리기까지 오지 않는다.

`apps/server/src/static.ts`:

```ts
import { relative, resolve, sep } from 'node:path';
import fastifyStatic from '@fastify/static';
import type { FastifyInstance, FastifyReply, FastifyRequest } from 'fastify';
import { sendNotFound } from './errors';

/** 해시가 붙은 Vite 산출물(dist/assets 바로 아래 파일)은 1년, index.html은 매번 확인, 나머지는 1시간 */
export function cacheControlFor(relPath: string): string {
  const path = relPath.split(sep).join('/');
  if (path === 'index.html') return 'no-cache';
  if (/^assets\/[^/]+$/.test(path)) return 'public, max-age=31536000, immutable';
  return 'public, max-age=3600';
}

/** index.html로 돌려보낼 화면 경로인지: GET/HEAD, /api·/socket.io 밖, 확장자 없음 */
export function isSpaRoute(method: string, url: string): boolean {
  if (method !== 'GET' && method !== 'HEAD') return false;
  const pathname = url.split('?')[0] ?? '/';
  if (pathname === '/api' || pathname.startsWith('/api/')) return false;
  if (pathname === '/socket.io' || pathname.startsWith('/socket.io/')) return false;
  return !/\.[A-Za-z0-9]+$/.test(pathname);
}

/** WEB_DIST 폴더를 정적 서빙하고, 화면 경로는 index.html로 돌려준다 */
export function registerWebStatic(app: FastifyInstance, webDist: string): void {
  const root = resolve(webDist);
  app.register(fastifyStatic, {
    root,
    wildcard: true,
    cacheControl: false,
    setHeaders: (reply, path) => {
      reply.header('cache-control', cacheControlFor(relative(root, path)));
    },
  });
  app.setNotFoundHandler((request: FastifyRequest, reply: FastifyReply) => {
    if (isSpaRoute(request.method, request.url)) {
      return reply.header('cache-control', 'no-cache').sendFile('index.html');
    }
    return sendNotFound(request, reply);
  });
}
```

`app.ts` — import에 `sendNotFound`, `registerWebStatic`을 더하고 `return app` 앞에서 고른다. 고친 뒤 파일 전체:

`apps/server/src/app.ts`:

```ts
import { EventEmitter } from 'node:events';
import fastifyCookie from '@fastify/cookie';
import fastifyRateLimit from '@fastify/rate-limit';
import Fastify, { type FastifyInstance } from 'fastify';
import { API } from '@4this/shared';
import { readSessionToken, resolveSession, type Auth } from './auth/session';
import type { Config } from './config';
import type { Db } from './db';
import { registerErrorHandlers, sendNotFound } from './errors';
import { registerAdminRoutes } from './routes/admin';
import { registerAuthRoutes } from './routes/auth';
import { registerMeRoutes } from './routes/me';
import { registerWorldRoutes } from './routes/world';
import { registerWebStatic } from './static';

/** 서버 안에서 주고받는 이벤트. wj#3의 소켓 계층이 world:changed를 받아 브로드캐스트한다 */
export type ServerEvents = { 'world:changed': [] };

declare module 'fastify' {
  interface FastifyInstance {
    config: Config;
    db: Db;
    events: EventEmitter<ServerEvents>;
  }
  interface FastifyRequest {
    auth: Auth;
  }
}

export interface AppOptions {
  config: Config;
  db: Db;
}

/** 서버 앱을 만든다. 테스트는 listen 없이 app.inject()로 부른다 */
export function buildApp({ config, db }: AppOptions): FastifyInstance {
  const app = Fastify({
    logger: false,
    // 같은 기기·사설망(nginx, Docker)의 프록시만 믿는다. true면 X-Forwarded-For 위조로 시도 제한을 우회할 수 있다
    trustProxy: config.trustProxy ? 'loopback,uniquelocal' : false,
  });
  app.decorate('config', config);
  app.decorate('db', db);
  app.decorate('events', new EventEmitter<ServerEvents>());
  // 객체는 기본값으로 못 넣는다(Fastify 5). 자리만 잡고 onRequest 훅에서 채운다
  app.decorateRequest('auth');

  registerErrorHandlers(app);
  app.register(fastifyCookie, { secret: config.sessionSecret });
  app.register(fastifyRateLimit, { global: false });

  app.register(async (api) => {
    // 쿠키 sid → sessions → member/admin. 없거나 만료면 guest
    api.addHook('onRequest', async (request) => {
      request.auth = resolveSession(db, readSessionToken(request));
    });
    api.get(API.health, async () => ({ ok: true }));
    registerAuthRoutes(api);
    registerWorldRoutes(api);
    registerMeRoutes(api);
    registerAdminRoutes(api);
  });

  // WEB_DIST가 있으면 웹 빌드를 같이 서빙한다 (컨테이너 1개 배포)
  if (config.webDist) registerWebStatic(app, config.webDist);
  else app.setNotFoundHandler(sendNotFound);

  return app;
}
```

## 백업

서버가 도는 중에도 SQLite 온라인 백업으로 일관된 파일을 받을 수 있다. 결과는 `world-YYYYMMDD.db`(한국 날짜) 파일 하나다.

**브라우저:** 관리자로 로그인 → 관리자 화면 → **백업** 버튼.

**curl:** 관리자 로그인 쿠키를 파일에 저장한 뒤 그 쿠키로 받는다. 로그인 시도는 IP당 분당 5회로 제한된다.

```bash
curl -c admin.cookies -H 'content-type: application/json' \
  -d '{"password":"<ADMIN_PASSWORD>"}' http://localhost:8080/api/auth/admin
curl -b admin.cookies -OJ http://localhost:8080/api/admin/backup   # world-YYYYMMDD.db 저장
rm admin.cookies
```

HTTPS 도메인 뒤라면 `http://localhost:8080` 자리에 `https://world.example.com`을 쓴다. 매일 받으려면 위 세 줄을 cron에 넣는다.

## 리버스 프록시 (nginx, HTTPS)

Socket.IO가 WebSocket을 쓰므로 `Upgrade`·`Connection` 헤더를 넘겨야 한다. `.env`에 `TRUST_PROXY=1`을 넣어야 로그인 시도 제한이 프록시 IP가 아닌 실제 접속자 IP로 동작한다.

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 443 ssl;
    http2 on;
    server_name world.example.com;

    ssl_certificate     /etc/letsencrypt/live/world.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/world.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 120s;
    }
}

server {
    listen 80;
    server_name world.example.com;
    return 301 https://$host$request_uri;
}
```

프록시를 쓰면 compose의 포트를 바깥에 열 필요가 없다. `ports`를 `'127.0.0.1:8080:8080'`으로 바꾸면 같은 서버의 nginx만 접근할 수 있다.
