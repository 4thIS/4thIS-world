# 4thIS-world 구현 플랜 개요

> **For agentic workers:** 이 문서는 16개 PR 플랜의 목차와 공통 규칙이다. 실제 작업은 각 PR 플랜 파일을 superpowers:subagent-driven-development(권장) 또는 superpowers:executing-plans로 Task 단위로 실행한다.

**Goal:** 스펙(`docs/superpowers/specs/2026-10-21-4this-world-design.md`)의 4thIS-world를 4명이 인당 PR 4개, 총 16개 PR로 완성한다.

**Architecture:** npm workspaces 모노레포. `packages/shared`(계약·캠퍼스 데이터·placement 엔진), `apps/server`(Fastify + Socket.IO + SQLite), `apps/web`(React + R3F). 위치는 각 브라우저가 계산하고 서버는 저장·인증·중계만 한다.

**Tech Stack:** Node 24 · TypeScript ~5.9.3 · zod 4 · vitest 5 · React 19.3 · Vite 8 · three 0.186 · @react-three/fiber 9 · drei 10 · zustand 5 · Fastify 5 · Socket.IO 4.8 · better-sqlite3 13 · bcryptjs 3 · Playwright 1.64 · Docker

## Global Constraints (모든 플랜에 적용)

- Node `>=24`, npm workspaces, `package-lock.json` 커밋. TypeScript는 `~5.9.3` 고정.
- 모든 패키지는 ESM. `@4this/shared`는 빌드하지 않고 TS 소스를 바로 import한다.
- 공용 타입·스키마·경로·이벤트는 **`@4this/shared`에서만** 가져온다. 같은 타입을 다른 곳에 다시 정의하지 않는다.
- 시각은 KST, `packages/shared/src/time.ts`만 쓴다. 랜덤이 화면 결과에 영향을 주면 `rand01()`(결정적)을 쓴다.
- 좌표계: 단위 m, +x 동쪽, +z 남쪽(정문), 캠퍼스 x·z ∈ [-25, 25], `facing` = `rotation.y`(0이면 +z를 봄), 층 높이 3.2 m.
- 파스텔 톤: 배경 `#fbeff6`, 글자 `#5b4d6b`, 카드 `rgba(255,255,255,0.85)`, 강조 분홍 `#ffb3c7`, 라벤더 `#c9bdf2`. 토큰은 `apps/web/src/ui/tokens.css`.
- 코드 스타일: Prettier(작은따옴표, 세미콜론, 100자). 주석과 사용자 문구는 한국어.
- 커밋: `feat:`/`fix:`/`chore:`/`test:`/`docs:` + 한국어 설명. PR 제목: `[cw#2] placement 엔진`.
- 남의 소유 파일(스펙 §12.2, `.github/CODEOWNERS`)은 고치지 않는다. 꼭 필요하면 소유자에게 먼저 말하고 리뷰를 받는다.

## 시작 전 준비 (저장소 관리자, 1회)

1. **권한**: 네 명 모두 저장소 `Write` 이상이어야 개인 브랜치를 push할 수 있다(지금 일부는 `Read`). Settings → Collaborators and teams에서 바꾼다.
2. **머지 방식**: Settings → General → Pull Requests에서 **Allow merge commits만 켜고** squash·rebase는 끈다(개인 브랜치를 계속 쓰기 때문, 스펙 §12.6).
3. **브랜치 보호** (`main`): PR 필수, 승인 1명, status check `ci / check` 필수, 직접 push 금지. CI가 cw#1에서 처음 생기므로 cw#1 머지 직후에 켠다.
4. **브랜치 만들기**: 이 문서와 스펙이 들어 있는 `main`을 push한 뒤, 각자 자기 브랜치를 만든다.
   ```bash
   git fetch origin && git checkout -b <cw|wj|hm|th> origin/main && git push -u origin HEAD
   ```

## PR 하나의 진행 방법

1. 개인 브랜치를 최신으로 맞춘다: `git fetch origin && git merge origin/main`
2. 해당 플랜 파일을 열고 Task를 순서대로 진행한다. Claude Code를 쓰면 이렇게 요청한다:
   `docs/superpowers/plans/2026-10-21-<플랜>.md 를 superpowers:subagent-driven-development 로 실행해줘`
3. 모든 Task가 끝나면 전체 검사를 돌린다:
   `npm run typecheck && npm run lint && npm run format:check && npm test && npm run build`
4. push하고 PR을 연다. 제목은 `[<브랜치>#<번호>] <플랜 제목>`, 본문은 PR 템플릿을 채운다.
5. 리뷰어 1명 이상 승인, CI 통과 → **Create a merge commit**으로 머지한다.
6. 단톡방에 "<PR> 머지됨"을 알리고, 이 PR을 선행으로 둔 사람이 자기 브랜치에 `origin/main`을 merge한다.

## 계약을 바꿔야 할 때

`packages/shared/src/schema/*`, `apps/web/src/world/contracts.ts`, `apps/web/src/ui/contracts.ts`는 4명이 함께 쓰는 계약이다.

1. 단톡방에 바꿀 내용(필드 이름·타입)을 먼저 올린다.
2. 계약만 바꾸는 작은 PR을 따로 열고 cw가 승인한다.
3. 머지 뒤 모두 `origin/main`을 merge한다.

## 완성 기준

- cw#4의 Playwright E2E가 통과한다: 가입 → 관리자 승인 → 캐릭터 등장 → 조종 → 두 번째 브라우저에서 움직임 확인.
- `docker compose up -d`로 띄운 컨테이너에서 같은 시나리오가 손으로도 된다.
- 캐릭터 30명 픽스처로 일반 노트북에서 60 fps(hm#4에서 확인).
